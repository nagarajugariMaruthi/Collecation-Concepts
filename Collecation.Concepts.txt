# Java Collections — 2 Years Experience

## 1. What is the Collection Framework?

The **Java Collection Framework (JCF)** is a set of interfaces and classes used to store and manipulate groups of objects.

Main interfaces:

```text
Iterable
   |
Collection
   |
   +---- List
   |      +---- ArrayList
   |      +---- LinkedList
   |      +---- Vector
   |
   +---- Set
   |      +---- HashSet
   |      +---- LinkedHashSet
   |      +---- TreeSet
   |
   +---- Queue
          +---- PriorityQueue
          +---- Deque
                 +---- ArrayDeque

Map  (separate from Collection)
 |
 +---- HashMap
 +---- LinkedHashMap
 +---- TreeMap
 +---- Hashtable
```

---

# 2. Collection vs Collections

This is a common interview question.

### Collection

`Collection` is an **interface**.

```java
Collection<String> names = new ArrayList<>();
```

It provides methods such as:

```java
add()
remove()
size()
contains()
isEmpty()
clear()
```

### Collections

`Collections` is a **utility class**.

```java
Collections.sort(list);
Collections.reverse(list);
Collections.max(list);
Collections.min(list);
```

### Interview answer

> Collection is an interface used as the root interface for List, Set and Queue, whereas Collections is a utility class containing static methods for operating on collections.

---

# 3. List

A `List`:

* Allows duplicates
* Maintains insertion order
* Allows index-based access

Example:

```java
List<String> names = new ArrayList<>();

names.add("Java");
names.add("SQL");
names.add("Java");

System.out.println(names);
```

Output:

```text
[Java, SQL, Java]
```

Important implementations:

* ArrayList
* LinkedList
* Vector

---

# 4. ArrayList

`ArrayList` internally uses a **dynamic array**.

```java
ArrayList<String> list = new ArrayList<>();

list.add("Java");
list.add("Spring");
list.add("SQL");

System.out.println(list);
```

### Advantages

* Fast random access
* Allows duplicates
* Maintains insertion order
* Good for searching/accessing elements by index

```java
list.get(1);
```

### Time complexity

| Operation       | ArrayList              |
| --------------- | ---------------------- |
| get()           | O(1)                   |
| add() at end    | Usually O(1) amortized |
| search          | O(n)                   |
| remove by index | O(n)                   |

### 2-year interview answer

> I use ArrayList when I need frequent read/access operations and don't have frequent insertions or deletions in the middle of the list.

---

# 5. LinkedList

`LinkedList` is based on a **doubly linked list**.

```java
LinkedList<String> list = new LinkedList<>();

list.add("Java");
list.add("SQL");
list.addFirst("Spring");
list.addLast("Hibernate");

System.out.println(list);
```

It can work as both:

```text
List
Queue
Deque
```

### When would you use LinkedList?

When your application requires frequent insertion/removal operations at the beginning/end or deque-like operations.

However, don't say blindly that LinkedList is always faster for insertion. Finding the position can itself require O(n) traversal.

---

# 6. ArrayList vs LinkedList

Very important for 2-year interviews.

| ArrayList                                  | LinkedList                                   |
| ------------------------------------------ | -------------------------------------------- |
| Dynamic array                              | Doubly linked list                           |
| Fast random access                         | Slow random access                           |
| get(index) O(1)                            | get(index) O(n)                              |
| Middle insertion/removal requires shifting | Once node is located, link changes are cheap |
| Usually better cache locality              | More memory per element                      |
| Good for read-heavy lists                  | Useful for frequent deque operations         |

### Interview answer

> In most general-purpose applications, I prefer ArrayList because random access is efficient and it generally has better memory/cache behavior. I choose LinkedList when its deque operations or linked-node behavior actually fit the use case.

# 7. Set

A `Set` does **not allow duplicate elements**.

```java
Set<String> set = new HashSet<>();

set.add("Java");
set.add("SQL");
set.add("Java");

System.out.println(set);
```

Only one `"Java"` remains.

Main implementations:

```text
HashSet
LinkedHashSet
TreeSet
```

# 8. HashSet

`HashSet`:

* Does not allow duplicates
* Does not guarantee iteration order
* Uses hashing internally
* Allows one `null`

```java
HashSet<Integer> set = new HashSet<>();

set.add(10);
set.add(20);
set.add(10);

System.out.println(set);
```

Output contains:

```text
10
20
```

Order should not be relied upon.

---

# 9. LinkedHashSet

`LinkedHashSet` maintains **insertion order** while preventing duplicates.

```java
LinkedHashSet<String> set = new LinkedHashSet<>();

set.add("Java");
set.add("SQL");
set.add("Spring");
set.add("Java");

System.out.println(set);
```

Output:

```text
[Java, SQL, Spring]
```

### When to use?

When you need:

> **Unique values + insertion order**

---

# 10. TreeSet

`TreeSet` stores unique elements in **sorted order**.

```java
TreeSet<Integer> set = new TreeSet<>();

set.add(50);
set.add(10);
set.add(30);
set.add(20);

System.out.println(set);
```

Output:

```text
[10, 20, 30, 50]
```

It is generally implemented using a **Red-Black tree**.

Typical operations are O(log n).

---

# 11. HashSet vs LinkedHashSet vs TreeSet

| Feature           | HashSet                    | LinkedHashSet              | TreeSet                                       |
| ----------------- | -------------------------- | -------------------------- | --------------------------------------------- |
| Duplicate         | No                         | No                         | No                                            |
| Order             | No guarantee               | Insertion order            | Sorted order                                  |
| Typical operation | O(1) average               | O(1) average               | O(log n)                                      |
| Null              | One null generally allowed | One null generally allowed | Natural ordering generally doesn't allow null |

### Easy memory trick

```text
HashSet       → Unique
LinkedHashSet → Unique + Insertion Order
TreeSet       → Unique + Sorted
```

# 12. Queue

Queue generally follows:

```text
FIFO
First In → First Out
```

Example:

```java
Queue<String> queue = new LinkedList<>();

queue.offer("A");
queue.offer("B");
queue.offer("C");

System.out.println(queue.poll());
```

Output:

```text
A
```

Important methods:

```java
offer()  → insert
poll()   → remove and return head
peek()   → view head
```

---

# 13. PriorityQueue

`PriorityQueue` processes elements according to priority rather than insertion order.

```java
PriorityQueue<Integer> queue = new PriorityQueue<>();

queue.offer(30);
queue.offer(10);
queue.offer(20);

System.out.println(queue.poll());
```

Output:

```text
10
```

Default priority for numbers is natural ascending order.

Important:

> Iterating over a PriorityQueue does **not** guarantee that every element appears in sorted order. The head is the highest-priority element according to the queue's ordering.

---

# 14. Deque

`Deque` means:

> Double Ended Queue

You can insert and remove from both ends.

```java
Deque<String> deque = new ArrayDeque<>();

deque.addFirst("A");
deque.addLast("B");

System.out.println(deque.removeFirst());
System.out.println(deque.removeLast());
```

---

# 15. Stack

A stack follows:

```text
LIFO
Last In → First Out
```

Modern Java code generally prefers `Deque`/`ArrayDeque` rather than the legacy `Stack` class.

```java
Deque<Integer> stack = new ArrayDeque<>();

stack.push(10);
stack.push(20);
stack.push(30);

System.out.println(stack.pop());
```

Output:

```text
30
```

# 16. Map

This is extremely important.

`Map` stores data as:

```text
Key → Value
```

Example:

```java
Map<Integer, String> map = new HashMap<>();

map.put(101, "Maruthi");
map.put(102, "Ravi");
map.put(103, "Kiran");
```

Here:

```text
101 → Maruthi
102 → Ravi
103 → Kiran
```

Keys must be unique.

Values can be duplicated.

# 17. HashMap

`HashMap` is one of the most commonly used Java collections.

```java
HashMap<String, Integer> map = new HashMap<>();

map.put("Java", 90);
map.put("SQL", 80);
map.put("Spring", 85);

System.out.println(map.get("Java"));
```

Output:

```text
90
```

Characteristics:

* Key-value pairs
* No guaranteed iteration order
* One `null` key is allowed
* Multiple `null` values are allowed
* Average O(1) lookup/insert under normal conditions

# 18. How does HashMap work internally?

This is a **very important 2-year interview question**.

Suppose:

```java
Map<String, Integer> map = new HashMap<>();

map.put("Java", 100);
```

Conceptually:

```text
"Java"
   ↓
hashCode()
   ↓
hash
   ↓
bucket/index
   ↓
Node
   ↓
key + value
```

When retrieving:

```java
map.get("Java");
```

Java calculates the hash and finds the appropriate bucket, then compares keys using `equals()` when necessary.

Modern JDK implementations can convert a heavily-collided bucket into a tree structure under certain conditions, improving worst-case lookup behavior.

# 19. HashMap put() vs get()

### put()

```java
map.put("Java", 100);
```

Conceptually:

```text
Key
 ↓
hashCode()
 ↓
bucket
 ↓
store/reuse entry
```

### get()

```java
map.get("Java");
```

Conceptually:

```text
Key
 ↓
hashCode()
 ↓
bucket
 ↓
equals()
 ↓
Value
```

# 20. Why override equals() and hashCode()?

Very common interview question.

Suppose you have:

```java
class Employee {
    int id;
    String name;
}
```

If you want `HashSet` or `HashMap` to identify employees based on their logical identity, you need properly implemented:

```java
equals()
hashCode()
```

Important contract:

> If two objects are equal according to `equals()`, they must return the same `hashCode()`.

But the reverse is not required: two unequal objects can have the same hash code.

# 21. LinkedHashMap

`LinkedHashMap` maintains a predictable iteration order.

```java
Map<Integer, String> map = new LinkedHashMap<>();

map.put(1, "Java");
map.put(2, "SQL");
map.put(3, "Spring");

System.out.println(map);
```

Output:

```text
{1=Java, 2=SQL, 3=Spring}
```

A common use case is:

> Remove duplicates while preserving insertion order.

For example:

```java
String str = "programming";

Set<Character> set = new LinkedHashSet<>();

for (char ch : str.toCharArray()) {
    set.add(ch);
}

System.out.println(set);
```

# 22. TreeMap

`TreeMap` stores keys in sorted order.

```java
TreeMap<Integer, String> map = new TreeMap<>();

map.put(30, "C");
map.put(10, "A");
map.put(20, "B");

System.out.println(map);
```

Output:

```text
{10=A, 20=B, 30=C}
```

Typical operations are O(log n).

# 23. HashMap vs LinkedHashMap vs TreeMap

Remember:

```text
HashMap       → Fast lookup, no guaranteed order
LinkedHashMap → Fast lookup + insertion/access order
TreeMap       → Sorted keys
```

| Feature         | HashMap      | LinkedHashMap | TreeMap                             |
| --------------- | ------------ | ------------- | ----------------------------------- |
| Key-value       | Yes          | Yes           | Yes                                 |
| Order           | No guarantee | Predictable   | Sorted                              |
| Typical get/put | O(1) avg.    | O(1) avg.     | O(log n)                            |
| Null key        | One          | One           | Generally not with natural ordering |

# 24. Hashtable

`Hashtable` is a legacy synchronized map.

```java
Hashtable<Integer, String> table = new Hashtable<>();

table.put(1, "Java");
table.put(2, "SQL");
```

It does not allow:

```text
null key
null value
```

For modern concurrent applications, `ConcurrentHashMap` is generally preferred over `Hashtable`.

---

# 25. ConcurrentHashMap

Used when multiple threads access and modify a map concurrently.

```java
ConcurrentHashMap<Integer, String> map =
        new ConcurrentHashMap<>();

map.put(1, "Java");
map.put(2, "Spring");
```

It provides thread-safe operations without synchronizing the entire map for every operation in the way a simple synchronized map would.

# 26. Iterator

`Iterator` is used to traverse collections.

```java
List<String> list = new ArrayList<>();

list.add("Java");
list.add("SQL");
list.add("Spring");

Iterator<String> iterator = list.iterator();

while (iterator.hasNext()) {
    System.out.println(iterator.next());
}
```

Methods:

```java
hasNext()
next()
remove()
```

---

# 27. Why use Iterator.remove()?

This is an important practical question.

Don't do:

```java
for (String value : list) {
    if (value.equals("SQL")) {
        list.remove(value);
    }
}
```

This can cause `ConcurrentModificationException`.

Instead:

```java
Iterator<String> iterator = list.iterator();

while (iterator.hasNext()) {
    String value = iterator.next();

    if (value.equals("SQL")) {
        iterator.remove();
    }
}
```

# 28. Comparable

`Comparable` is used for **natural ordering**.

```java
class Employee implements Comparable<Employee> {

    int salary;

    Employee(int salary) {
        this.salary = salary;
    }

    @Override
    public int compareTo(Employee e) {
        return this.salary - e.salary;
    }
}
```

Then:

```java
Collections.sort(employees);
```

---

# 29. Comparator

`Comparator` is used when you want **custom sorting**.

```java
Comparator<Employee> comparator =
        (e1, e2) -> Integer.compare(e1.salary, e2.salary);

employees.sort(comparator);
```

You can create different comparators:

```text
sort by salary
sort by name
sort by age
sort by department
```

### Interview answer

> Comparable defines the natural ordering inside the class through `compareTo()`, whereas Comparator defines external/custom ordering through `compare()`.

# 30. Fail-Fast vs Fail-Safe

### Fail-fast

If a collection is structurally modified while iterating through a normal iterator, it may throw:

```text
ConcurrentModificationException
```

Examples include common iterators from:

```text
ArrayList
HashMap
HashSet
```

### Fail-safe / weakly consistent behavior

Concurrent collections such as:

```text
CopyOnWriteArrayList
ConcurrentHashMap
```

have different iteration semantics and generally don't throw `ConcurrentModificationException` merely because another thread modifies the collection.

For interviews, it's better to say **"fail-fast" and "weakly consistent/snapshot-style"** rather than treating every concurrent collection as literally fail-safe.

# 31. Generics

Generics provide type safety.

Without generics:

```java
List list = new ArrayList();

list.add("Java");
list.add(10);
```

With generics:

```java
List<String> list = new ArrayList<>();

list.add("Java");
list.add("Spring");
```

Now:

```java
list.add(10);
```

causes a compile-time error.

# 34. What a 2-Year Developer Should Be Able to Explain

Don't just memorize definitions. You should be able to explain **why you chose a collection**.

For example:

### Interviewer:

> You need unique customer IDs and don't care about order. Which collection?

**Answer:**

> I would use HashSet because I need uniqueness and don't require ordering.

### Interviewer:

> Unique customer IDs, but insertion order must be maintained?

**Answer:**

> I would use LinkedHashSet.

### Interviewer:

> Unique IDs in sorted order?

**Answer:**

> I would use TreeSet.

### Interviewer:

> Store employee ID and employee name?

**Answer:**

> I would use HashMap<Integer, String>.

### Interviewer:

> Store employee records and retrieve them frequently by ID?

**Answer:**

> I would consider HashMap<EmployeeId, Employee> because lookup by key is typically O(1) on average.

### Interviewer:

> Need sorted employee IDs?

**Answer:**

> TreeMap would be appropriate if sorted key order is required.
